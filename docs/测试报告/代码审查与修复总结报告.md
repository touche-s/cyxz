## 四、关键问题说明

### 4.1 P0：governance 越权接口可被直接调用（已修复）

`@EnableMethodSecurity` 缺失导致 `@PreAuthorize` 不生效，治理中心管理接口存在越权风险。修复为新增 `SecurityConfig` 继承公共配置并开启方法级授权，与 auth 服务保持一致。

### 4.2 P0：init.sql 无管理员种子数据（已修复）

全新部署后无人能进入管理后台。已新增站主 `admin / Admin@123`（bcrypt 哈希）并绑定 `SITE_OWNER` 角色。

### 4.3 P0：AI 审核 fail-open（已修复）

`AUTO_PASS_WITHOUT_KEY` 默认值改为 `false`，AI 审核 key 缺失时按 fail-closed 处理，配合超时降级兜底，避免"未审核即放行"。

### 4.4 P1：事务内发 MQ（4 处，已修复）

`register` / `batchOperate` / 建圈审批 / 入圈审批在事务内直发 RabbitMQ，事务回滚后事件残留、且占用 DB 事务时长。统一改为 `TransactionUtils.afterCommit`（无事务上下文时立即执行）。

### 4.5 P1：审核/举报 checkPending 读改写竞态（已修复）

`selectById → 改状态 → updateById` 之间并发审核会互相覆盖。改为 `LambdaUpdateWrapper` + `eq(status, PENDING)` 的 CAS 原子写，rows==0 抛「已被处理」，杜绝重复审核。

### 4.6 P1：会话未读数读改写丢更新（已修复）

`sendMessage` 读回会话自增、`markRead` 读回清零，并发发消息时互相覆盖。改为单条 `UPDATE` 原子自增/清零。

> **顺带发现（已彻底修复）**：conversation 表有 4 列（`user_id_1`/`user_id_2`/`unread_count_1`/`unread_count_2`）与 MyBatis-Plus 自动生成的列名（`user_id1`/`user_id2`/`unread_count1`/`unread_count2`）不一致——原 `selectById`/`updateById`/`insert` 在真实库都会报未知列，整个私信功能存在隐性断裂。已为 [ConversationPO](../../cyxz-message/src/main/java/com/cyxz/message/entity/ConversationPO.java) 4 个字段补 `@TableField` 显式列名对齐 DDL，不动表结构、已运行库无需迁移。

### 4.7 P1：多实例定时任务重复执行（已修复）

计数刷库任务多副本部署时同时执行会互相覆盖增量。新建 `RedisLockUtil`（SETNX + TTL 兜底），PostCountFlushTask / CommentCountFlushTask 加互斥锁。PostEsSyncService 重试任务基于 `rightPop` 出队本身原子，无需加锁。

### 4.8 P0 数据缺口：role 权限码缺失（本轮新发现并修复）

后端 [RoleAdminController](../../cyxz-auth/src/main/java/com/cyxz/auth/controller/RoleAdminController.java) 使用 `role:manage:list` / `role:manage:assign`，但 `sys_permission` 种子数据没有这两个码。授权链路是 DB 驱动的（无管理员通配），因此**全新部署时站主访问「角色权限」页也会 403**。已在 `init.sql` 补 34/35 号权限码并绑定站主与平台管理员（权限码总数 33→35）。

### 4.9 越权修复（已修复）

- `UploadController.deleteFile` 原先任意对象可删任意路径资源，改为按前缀白名单放行。
- 圈子帖子审核增加归属校验，圈主不能审核他圈帖子。
- 禁用用户在网关层统一拦截（Redis 标记，7 天 TTL）。
