# 社区氛围功能设计

> 社区氛围是让用户"留下来"的关键。本文档分已实现和规划两部分，已实现内容均基于代码核对。

## 设计定位

二次元社区的氛围来自三个层面：

1. **互动反馈**：发帖有人看、点赞收藏有反馈、关注动态能回流
2. **成长激励**：签到打卡、经验等级、徽章成就，让用户有持续登录动力
3. **圈层认同**：角色应援、谷子展示、同担社交，强化圈内归属感

当前项目已实现第一层（互动反馈），第二层和第三层为规划重点。

## 一、已实现

> 基于 `cyxz-post` / `cyxz-comment` / `cyxz-circle` / `cyxz-user` / `cyxz-message` 模块代码核对。

### 1. 帖子互动

**点赞 / 收藏 / 浏览**（`PostInteractionServiceImpl`）：

| 接口 | 说明 | 技术细节 |
|---|---|---|
| `PUT /post/{postId}/like` | 点赞（幂等） | UPSERT 一条 SQL：rows=1 新增, rows=2 恢复, rows=0 幂等 |
| `DELETE /post/{postId}/like` | 取消点赞（幂等） | 条件 UPDATE：仅 status=1 时更新为 0 |
| `PUT /post/{postId}/collect` | 收藏（幂等） | 同点赞机制 |
| `DELETE /post/{postId}/collect` | 取消收藏（幂等） | 同取消点赞机制 |
| `POST /post/{postId}/view` | 记录浏览 | Redis 去重 + 增量计数，定时刷库 |

**计数方案**：关系表照常写，计数通过 Redis Hash 增量记录，`CountFlushTask` 每 30 秒统一刷库，避免高并发下频繁 UPDATE。

**互动统计**：

- `GET /post/stats`：当前用户的帖子总浏览、总点赞、总收藏
- `GET /post/dashboard`：数据中心仪表盘（概览统计、月度趋势、板块分布、Top 作品）
- `GET /post/today`：今日新增点赞、收藏、评论数（创作首页工作台）
- `GET /post/received-likes`：收到的点赞列表（互动管理）
- `GET /post/top`：作品排行榜（按浏览量倒序）

### 2. 评论互动

**评论 / 回复 / 点赞**（`CommentController` + `CommentServiceImpl`）：

| 接口 | 说明 |
|---|---|
| `POST /comment` | 发表评论（含完整用户信息，前端可直接插入列表） |
| `DELETE /comment/{commentId}` | 删除评论（逻辑删除） |
| `GET /comment/list` | 帖子评论列表（仅顶级评论，含嵌套子回复第一页） |
| `GET /comment/replies` | 某条评论的子回复分页 |
| `PUT /comment/{commentId}/like` | 点赞评论（幂等） |
| `DELETE /comment/{commentId}/like` | 取消点赞评论（幂等） |
| `GET /comment/received` | 收到的评论列表（互动管理） |
| `GET /comment/manage` | 评论管理（自己帖子下的评论，可按帖子筛选） |

**嵌套回复**：评论为两级结构（顶级评论 + 子回复），避免无限嵌套导致的查询复杂度。

**计数同步**：评论点赞通过 Redis Hash 增量记录，`CommentCountFlushTask` 定时刷库。

### 3. 关注关系

**关注 / 取关 / 列表**（`UserProfileController` + `FollowServiceImpl`）：

| 接口 | 说明 |
|---|---|
| `POST /user/{targetUserId}/follow` | 关注用户（幂等，并发安全） |
| `DELETE /user/{targetUserId}/follow` | 取消关注 |
| `GET /user/{targetUserId}/is-following` | 是否关注 |
| `GET /user/{targetUserId}/is-mutual-following` | 是否互相关注（私信按钮判断） |
| `GET /user/following` | 关注列表（分页） |
| `GET /user/followers` | 粉丝列表（分页） |
| `GET /user/follow-stats` | 关注数、粉丝数、新增粉丝数 |
| `GET /user/internal/following-ids` | 内部接口：关注用户 ID 列表（供 post 拉取关注动态） |

**关注动态流**：`GET /post/following` 拉模式时间线，查关注用户最近发的帖子。

**关注通知**：关注成功后通过 MQ 异步发 `USER_FOLLOWED` 通知给被关注者。

### 4. 圈子归属

**加入 / 退出 / 成员计数**（`CircleController`）：

| 接口 | 说明 |
|---|---|
| `GET /circle/list` | 全量启用圈子列表 |
| `GET /circle/{circleId}` | 圈子详情（含是否已加入） |
| `GET /circle/hot` | 热门圈子（按成员数降序） |
| `GET /circle/joined` | 已加入的圈子 |
| `POST /circle/{circleId}/join` | 加入圈子（原子递增 member_count） |
| `DELETE /circle/{circleId}/join` | 退出圈子（原子递减 member_count） |

**计数同步**：`CircleCountFlushTask` 每 60 秒通过 Feign 批量拉取各圈子已发布帖子数，覆盖写入 `post_count`，无增量写入、无 Redis 中转、无重复计数。

**发布权限**：`GET /circle/internal/{circleId}/publishable` 校验圈子存在 + 启用 + 用户已加入。

### 5. 消息通知反馈

**通知中心 + 私信**（`cyxz-message`）：

- 10 种通知类型：点赞、评论、回复、收藏、关注、审核通过/拒绝、帖子/评论下架、举报结果
- MQ 异步落库 + WebSocket 实时推送
- 私信会话列表、历史消息、发送、标记已读、总未读数

详见 [消息通知与关注动态方案.md](./消息通知与关注动态方案.md)。

### 6. 内容质量保障

**敏感词检测**（`SensitiveWordService`）：

- `POST /post/check-sensitive`：发布前自行检测，返回命中敏感词列表
- 静态文件加载，启动时读入内存

**AI 审核**（`cyxz-ai` + `AiReviewService`）：

- 文本审核：DeepSeek LLM 判断违规
- 图片审核：通义千问 VL 多模态判断
- fail-closed：AI 不可用时拒绝发布

详见 [AI能力设计.md](./AI能力设计.md)。

## 二、规划

### 1. 签到打卡系统（P0）

**Redis Bitmap 存签到状态**：

```
Key:   sign:{userId}:{yyyyMM}
Value: Bitmap，第 N 位表示当月第 N 天是否签到
```

| 操作 | Redis 命令 | 说明 |
|---|---|---|
| 签到 | `SETBIT sign:{uid}:{ym} {day} 1` | O(1) |
| 查今日 | `GETBIT sign:{uid}:{ym} {day}` | O(1) |
| 查本月 | `BITFIELD sign:{uid}:{ym} GET u{days} 0` | 一次取整月 |
| 连续天数 | `BITCOUNT` + 从右往左找第一个 0 | O(N) 但 N≤31 |

**内存对比**：1 万用户一年签到数据，Bitmap 占 480KB，MySQL 每天一行占 360MB。

**签到奖励**：

| 连续天数 | 奖励 |
|---|---|
| 1-6 天 | 每日 +10 经验 |
| 7 天 | +50 经验 + 铜色签到徽章 |
| 30 天 | +200 经验 + 银色签到徽章 |
| 100 天 | +500 经验 + 金色签到徽章 |
| 365 天 | +2000 经验 + 彩色签到徽章 + 专属称号 |

**补签机制**：每月 3 次免费补签，超过用积分补签（50 积分/次），只补最近 7 天。

### 2. 成就系统（P0）

**经验值来源**：

| 行为 | 经验值 | 每日上限 |
|---|---|---|
| 签到 | +10 | 10 |
| 发布帖子 | +20 | 60 |
| 帖子被点赞 | +1/个 | 30 |
| 帖子被收藏 | +2/个 | 20 |
| 发表评论 | +5 | 25 |
| 被关注 | +3 | 15 |
| 帖子被加精 | +100 | 无上限 |

**等级体系**：萌新(0) → 潜水员(100) → 冒泡(500) → 常驻(2000) → 活跃(8000) → 大佬(50000) → 传说(200000)

**徽章检查策略模式**：

```java
public interface BadgeChecker {
    String getBadgeCode();
    boolean check(Long userId, ExpSource trigger);
}

@Component
public class PopularAuthorChecker implements BadgeChecker {
    @Override
    public String getBadgeCode() { return "POPULAR_AUTHOR"; }
    @Override
    public boolean check(Long userId, ExpSource trigger) {
        if (trigger != ExpSource.LIKE_RECEIVED) return false;
        return postMapper.existsPostWithLikes(userId, 100);
    }
}
```

每种徽章一个 Checker，新增徽章只加类不改现有逻辑——开闭原则。经验值每日上限用 Redis 计数器控制，避免刷经验。

### 3. 角色应援榜（P1）

**Redis ZSet 排行榜**：

```
Key:   rank:vote:{circleId}:{yyyyMMdd}
Score: 票数
Value: 角色ID
```

| 操作 | Redis 命令 | 说明 |
|---|---|---|
| 投票 | `ZINCRBY rank:{cid}:{date} 1 {charId}` | O(logN) 原子操作 |
| 查排名 | `ZREVRANK rank:{cid}:{date} {charId}` | O(logN) |
| TOP 20 | `ZREVRANGE rank:{cid}:{date} 0 19 WITHSCORES` | O(logN+M) |

**每日投票限制**：`SADD rank:vote:user:{uid}:{date} {circleId}` 返回 1 允许，返回 0 拒绝。

**定时快照**：每日 0:05 将昨日 TOP 100 存入 DB，Redis 只保留 7 天热数据。

### 4. 谷子展示柜（P1）

- 个人主页 → 谷子柜 Tab → 瀑布流
- 图片 + IP 来源 + 获取方式 + 价格区间 + 备注
- 其他用户可点赞"眼馋了"
- 前端用 CSS `column-count` 或虚拟列表，IntersectionObserver 触发下一页

### 5. 圈子角色权限（P2）

**RBAC 权限模型**：

```
圈主（创建者）
  ├── 管理员（圈主任命）
  │     ├── 置顶帖子
  │     ├── 删除帖子
  │     └ 设置公告
  └── 普通成员
        ├── 发帖
        ├── 评论
        └ 退出圈子
```

**注解 + AOP 声明式校验**：

```java
@RequireCircleRole(minRole = 1)
@PostMapping("/circle/{circleId}/post/{postId}/pin")
public Result<Void> pinPost(@PathVariable Long circleId, @PathVariable Long postId) {
    circleService.pinPost(circleId, postId);
    return Result.success();
}
```

和 Spring Security 的 `@PreAuthorize` 思路一致，但更轻量。

### 6. 每日任务系统（P2）

**Redis Hash 存任务进度**：

```
Key:   task:daily:{userId}:{yyyyMMdd}
Field: task_code (SIGN / COMMENT / LIKE / VIEW)
Value: 完成次数
```

Key 带日期后缀天然实现按天隔离，不需要定时任务重置。旧 Key 设 3 天过期自动清理。

**任务清单**：

| 任务 | 条件 | 奖励 |
|---|---|---|
| 每日签到 | 完成签到 | +10 经验 |
| 发表 1 条评论 | 评论 1 次 | +5 经验 |
| 点赞 3 个帖子 | 点赞 3 次 | +5 经验 |
| 浏览 5 个帖子 | 浏览 5 次 | +5 经验 |

全部完成额外奖励：+20 经验 + 1 个每日宝箱（随机积分 5-50）。

## 三、技术亮点（面试用）

> 技术亮点总览见 [README](../../README.md#技术亮点)，以下为本模块特有亮点。

| 技术 | 用在哪 | 面试怎么讲 |
|---|---|---|
| UPSERT 幂等 | 点赞收藏 | "一条 SQL 完成：rows=1 新增, rows=2 恢复, rows=0 幂等，无需先查再写" |
| Redis Bitmap | 签到存储（规划） | "1 万用户一年签到数据只占 480KB，对比 MySQL 的 360MB" |
| Redis ZSet | 排行榜（规划） | "ZINCRBY 原子操作支撑高并发投票，ZREVRANGE 取 TOP20 是 O(logN+M)" |
| 策略模式 | 徽章检查（规划） | "每种徽章一个 Checker，新增徽章不改现有代码——开闭原则" |
| Key 设计 | 每日任务（规划） | "用日期后缀天然隔离，不需要定时任务重置" |

## 四、实施优先级

```
第一批（先做，技术亮点最强）
  ├─ 签到打卡（Redis Bitmap）P0
  └─ 成就系统（策略模式 + 经验值模型）P0

第二批（顺手做，性价比高）
  ├─ 角色应援榜（Redis ZSet + 定时快照）P1
  └─ 每日任务（Redis Hash + Key 设计）P2

第三批（有空再做，偏前端）
  ├─ 谷子展示柜（瀑布流 + 标签筛选）P1
  └─ 圈子角色权限（RBAC + AOP 注解）P2
```
