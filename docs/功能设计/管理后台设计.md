# 管理后台设计

> 后台是次元小站的运营中枢。本文档分已实现和规划两部分，已实现内容均基于代码核对。

## 设计定位

借鉴 OA/ERP 的审批流、审计和权限思路，让后台从"数据查看器"升级为"可运营的管理系统"。

- **流程闭环**：内容发布 → AI 初审 → 人工兜底 → 通知作者，每步可追溯
- **权限最小化**：管理员操作通过注解校验，非 admin 角色一律拒绝
- **状态机驱动**：帖子状态流转通过 `ALLOWED_TRANSITIONS` 表强约束，避免非法跃迁
- **AI 优先 + 人工兜底**：常规内容走 AI 自动审核，异常或边界场景转人工

## 一、已实现

> 基于 `cyxz-common` / `cyxz-gateway` / `cyxz-post` / `cyxz-circle` 模块代码核对。

### 1. 管理员鉴权机制

采用"网关注入信任头 + 注解校验"的两段式设计，不依赖会话或独立鉴权服务。

**网关侧**（`JwtAuthFilter`）：

- 校验 JWT 后从中提取 `role`，无条件注入 `X-User-Role` 请求头
- 关键防伪造：入口处先 `headers.remove("X-User-Id")` / `headers.remove("X-User-Role")`，避免外部伪造
- 内部接口（`/internal/`）一律 403 拒绝外部访问，Feign 直调不经网关不受影响

**服务侧**（`cyxz-common`）：

- `@AdminUser` 注解（`PARAMETER` 级别），标注在 Controller 方法参数上
- `AdminUserResolver` 实现 `HandlerMethodArgumentResolver`，从 `X-User-Role` 头读取角色
- 非 `admin` 角色抛 `BusinessException(ErrorCode.FORBIDDEN, "仅管理员可执行此操作")`
- `WebMvcConfig` 注册该 Resolver，所有引入 `cyxz-common` 的服务自动生效

**使用示例**：

```java
@PutMapping("/admin/review/{postId}/approve")
public Result<Void> approvePost(@AdminUser Object admin, @PathVariable Long postId) {
    postService.approvePost(postId);
    return Result.success("审核通过");
}
```

`@AdminUser Object admin` 参数仅作鉴权用途，方法内不使用其值。这种写法让鉴权逻辑在方法签名上显式可见，比 `@PreAuthorize` 注解更直观。

### 2. 帖子状态机

`PostStatus` 常量类定义 5 种状态与合法流转表：

```
0 草稿 DRAFT       → 待审核 / 已删除
1 待审核 PENDING   → 已通过 / 拒绝 / 草稿 / 已删除
2 已通过 APPROVED  → 已删除
3 拒绝 REJECTED    → 草稿 / 已删除
4 已删除 DELETED   → 草稿
```

- `ALLOWED_TRANSITIONS` 用 `Map<Integer, Set<Integer>>` 表达流转规则
- `canTransition(from, to)` 校验合法性，`from == to` 直接放行
- 任意状态均可软删除（`DELETED`），符合"用户随时可删自己帖子"的直觉
- `STATUS_LABEL` 提供中文标签，错误信息友好（"不允许从 已通过 直接变更为 拒绝"）

### 3. 帖子审核流程

`PostController` 暴露 3 个审核接口，全部 `@AdminUser` 鉴权：

| 接口 | 说明 |
|---|---|
| `GET /post/admin/review/pending` | 待审核帖子分页列表，按创建时间升序 |
| `PUT /post/admin/review/{postId}/approve` | 审核通过 |
| `PUT /post/admin/review/{postId}/reject` | 审核拒绝，请求体带 `reason` |

**`approvePost` 流程**：

1. 查帖子，校验存在性
2. 校验当前状态必须为 `PENDING`
3. `canTransition` 二次校验状态流转合法性
4. 更新 `status = APPROVED`，清空 `reviewReason`
5. 清缓存 `evictDetailCache`
6. 发 ES 同步消息（`CREATE` action）

**`rejectPost` 流程**：

1. 查帖子，校验存在性
2. `canTransition` 校验
3. 更新 `status = REJECTED`，记录 `reviewReason`
4. 清缓存

### 4. AI 自动审核 + 人工兜底

帖子创建时自动走 AI 审核，结果通过 `handleReviewResult` 处理：

- **AI 通过**：`status = APPROVED`，清 `reviewReason`，清缓存，发 ES 同步，发 `POST_APPROVED` 通知
- **AI 拒绝**：`status = REJECTED`，记 `reviewReason`，清缓存，发 `POST_REJECTED` 通知
- **AI 异常**：`handleReviewFailure` 保持 `status = PENDING`，标记 `reviewReason = "AI审核服务异常，待人工审核"`，等待管理员在后台手动处理

通知通过 `sendReviewNotify` 走 RabbitMQ 异步发送，`senderId = 0L` 表示系统通知。

### 5. 圈子管理

`CircleController` 的写操作均要求 `@AdminUser`：

| 接口 | 说明 |
|---|---|
| `POST /circle` | 创建圈子，自动生成 slug，初始化默认板块 |
| `PUT /circle/{circleId}` | 更新圈子资料（name/intro/avatar/cover） |
| `DELETE /circle/{circleId}` | 逻辑删除圈子 |
| `PUT /circle/{circleId}/sections` | 全量替换圈子板块配置（先删后插） |

圈子板块采用"模板 + 关联"两层模型：

- `SectionTemplateController`（`/admin/section-template`）管理全站板块模板，仅管理员可操作
- 模板 `applicable_type` 字段区分适用创作类型：`ALL` / `NORMAL` / `ARTICLE`
- 创建圈子时自动 `initDefaultSections`：取所有 `ALL` 模板初始化，首个设为默认

### 6. 敏感词检测

`SensitiveWordService` 提供发布前检测能力：

- `POST /post/check-sensitive`：用户发布前自行检测标题和正文，返回命中敏感词列表
- 静态文件加载，启动时读入内存，避免每次查库
- 命中后由前端拦截或提示用户修改

### 7. ES 全量同步

`EsFullSyncRunner` 启动时全量同步已发布帖子到 Elasticsearch，供后续搜索使用。审核通过/删除帖子时通过 MQ 事件增量同步。

## 二、规划

### 1. 工作台与数据看板

- **首页概览**：今日新增用户、今日帖子数、待处理举报、待处理工单四卡片
- **趋势图**：近 30 天帖子发布趋势、用户注册趋势（折线图）
- **内容分布**：各圈子帖子数占比（饼图）、各分类分布（条形图）
- **异常预警**：连续 3 天无新帖的圈子、评论数骤降的圈子、积压超 7 天的举报

### 2. 举报审核系统

核心内容治理模块，规划完整闭环：

- 举报列表：状态（待处理/已处理/已驳回）、类型（帖子/评论）、超时标记
- 举报详情：被举报内容上下文 + 处理区域
- 处理动作：通过举报（隐藏/删除/警告）或驳回，必填处理说明
- 处理时间线：记录每步操作人、时间、动作、说明
- 超时标红：超过 24h 未处理标红提示

### 3. 用户管理

- 用户列表：ID/昵称搜索、注册时间筛选、状态筛选
- 操作：查看个人空间、禁用/启用用户
- 禁用确认：禁用后无法登录和发表内容，已有内容保留
- 可选同时隐藏所有帖子，记录禁用原因，可选通知用户

### 4. 操作日志审计

记录所有管理员敏感操作：

- 圈子：创建、编辑、停用、启用
- 内容：隐藏、恢复帖子/评论、处理举报
- 用户：禁用、启用、修改角色
- 配置：修改参数、修改分类/标签、发布公告

字段：时间、操作人、操作类型、操作对象、前状态、后状态、说明、IP、UA。保留 90 天，支持 CSV/Excel 导出。

### 5. 反馈工单系统

- 工单列表：状态（待处理/处理中/已解决/已关闭）、类型、优先级
- 工单详情：用户提交内容 + 处理时间线 + 操作区
- 状态变更 + 管理员回复 + 内部备注（仅管理员可见）
- 工单统计：本月新增/已解决/平均处理时长/类型分布

### 6. 运营配置

将硬编码规则提取为可配置参数：

- 内容规则：标题字数、内容最小字数、每日发帖/评论上限
- 举报规则：超时自动关闭天数、每人每日举报上限
- 通知规则：点赞/评论/关注通知开关
- 注册规则：新用户注册开关、用户名字数

每个参数显示：键名、当前值、默认值、说明、最后修改时间/人。即时生效无需重启。

### 7. 公告管理

- 列表：标题、状态、展示位置、创建时间
- 新增/编辑：标题、内容、展示位置（全站顶部/首页横幅/发现页）、起止时间、排序

### 8. 角色权限（RBAC）

```
普通用户        浏览、发帖、评论、点赞收藏、举报
内容审核员      查看和处理举报、隐藏内容、查看操作日志
超级管理员      全部权限 + 系统配置 + 角色分配
```

当前只有 `admin` 单一角色，未来扩展为多角色 + 资源粒度权限。

## 三、技术亮点（简历视角）

1. **两段式鉴权**：网关注入信任头 + 服务侧注解校验，防伪造剥离 + 显式声明，比单纯 Spring Security 更轻量
2. **状态机强约束**：`ALLOWED_TRANSITIONS` 表 + `canTransition` 校验，所有状态变更都走合法路径，错误信息友好
3. **AI + 人工兜底**：AI 异常时不放行也不拒绝，转 `PENDING` 等人工处理，避免误判
4. **审核通知联动**：审核结果通过 MQ 异步通知作者，业务事务与通知解耦
5. **ES 增量同步**：审核通过/删除时发 MQ 事件增量同步，启动时全量同步兜底
6. **模板 + 关联两层模型**：板块模板全站统一，圈子按需启用，保证命名一致性
7. **防内部接口外泄**：网关统一拦截 `/internal/` 路径，Feign 直调不经网关不受影响
