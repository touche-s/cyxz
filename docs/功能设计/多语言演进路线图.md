# 多语言演进路线图

> 本文档讲的是 **多语言（multi-language）架构演进**，即何时引入 Go / Python 等非 Java 语言，不是国际化（i18n）。当前项目 i18n 未实现，前端文案为硬编码中文。

## 设计原则

核心业务不动 Java，局部能力用最适合的语言补。判据：

1. 该模块是否独立能力（IM、AI、推送、文件处理）
2. 该语言是否明显更擅长这个场景
3. 拆出去后主业务是否更清晰

**已实现的多语言**：

| 语言 | 模块 | 职责 |
|---|---|---|
| Java | gateway / auth / user / post / comment / circle / upload / message / search | 全部主业务 |
| Python | `cyxz-ai`（FastAPI） | AI 内容审核（文本 + 图片） |

**跨语言通信**：Java → Python 走 HTTP（`RestTemplate`），Python 不存业务数据，只做计算返回结果。

### 2. i18n 现状

- **后端**：未实现 `MessageSource` / `LocaleResolver` / `@RequestHeader Accept-Language` 处理，错误信息为硬编码中文
- **前端**：未引入 `vue-i18n`，所有文案为硬编码中文
- **唯一 Locale 引用**：`UploadServiceImpl` 中 `java.util.Locale` 仅用于字符串大小写转换，与 i18n 无关

**结论**：当前项目定位为中文社区，i18n 暂无实现，列入长期规划。

## 二、已实现

> 基于 `cyxz-ai` 模块代码核对。

### Python cyxz-ai 服务

**技术栈**：FastAPI + uvicorn + httpx + pydantic + python-dotenv

**职责**：AI 内容审核（独立部署，不碰 DB/缓存/MQ）

**接口**：

| 接口 | 说明 |
|---|---|
| `POST /review` | 文本审核（DeepSeek LLM） |
| `POST /review/image` | 图片审核（通义千问 VL 多模态） |
| `GET /health` | 健康检查 |

**集成方式**：

- Java `AiReviewService` 通过 `RestTemplate` 调用
- `ai.review.url` / `ai.review.image-url` 配置外置
- fail-closed：AI 不可用时 Java 侧返回拒绝，主业务不受影响
- 异步调用：`CompletableFuture.runAsync` 不阻塞发帖响应

详见 [AI能力设计.md](./AI能力设计.md)。

## 三、规划

### 第一阶段：补实时能力（Go）

| 模块 | 语言 | 原因 |
|---|---|---|
| **私信 IM 服务** | Go | WebSocket 长连接、goroutine 管理并发连接天然优势、消息路由快 |
| **圈子群聊** | Go | 与私信同一套 WebSocket 连接，圈内消息广播 fan-out、在线人数统计 |
| **实时通知推送** | Go | 系统通知/评论/点赞的 SSE/WS 推送，与 IM 同技术栈可合并 |

**当前状态**：`cyxz-message` 已用 Java 实现单实例 WebSocket + 私信 + 通知推送，足够支撑当前规模。多实例部署或圈子群聊上线后考虑迁移到 Go。

**目标架构**：

```
当前：
  Java cyxz-message（通知落库 + WebSocket 推送 + 私信）

目标：
  Go cyxz-im（WebSocket + 私信 + 圈子群聊 + 实时推送）
  Java cyxz-message（系统通知落库 + 离线消息聚合）
```

**消息模型**：

```sql
chat_message (
  id, chat_type, target_id, sender_id, content,
  image_url, create_time
)
```

- `chat_type = PRIVATE` → `target_id` = 对方用户 ID（私聊）
- `chat_type = CIRCLE` → `target_id` = 圈子 ID（圈聊）

一个 WebSocket 连接承载私聊和圈聊，前端聊天面板切频道。

**圈子群聊额外能力**：

- 实时在线人数（Redis set + 心跳）
- 新帖自动推送到圈聊通知（Post 服务发 MQ → Go 消费 → 广播）
- 系统消息（精华帖推送、圈规更新提醒）

**集成方式**：

- 前端直接连 Go IM 服务的 WebSocket，私聊和圈聊复用同一连接
- Java 需要推送时通过 Redis pub/sub 或 HTTP 通知 Go 服务
- Go 服务通过 HTTP 调 Java 获取用户信息、加入圈子列表
- 消息持久化到 MySQL，Java 和 Go 共享同一消息表

### 第二阶段：补 AI 能力扩展（Python）

当前 `cyxz-ai` 只做审核，规划扩展为完整 AI 能力：

| 能力 | 说明 |
|---|---|
| 创作辅助 | 标签建议、标题润色、圈子建议、长文摘要 |
| 圈子 RAG | IP 百科知识库检索 + LLM 生成回答 |
| 次元小助手 | Agent + Function Calling + 对话记忆 |
| 运营辅助 | 圈报生成、话题推荐、内容聚类 |

详见 [AI能力设计.md](./AI能力设计.md) 规划部分。

**集成方式**：

- Java 通过 HTTP 调 Python AI 服务
- Python 不存业务数据，只做计算和返回结果
- 超时降级：AI 服务不可用时不影响主流程

### 第三阶段：补工程效率（Go / Python）

| 模块 | 语言 | 原因 |
|---|---|---|
| **热榜/推荐流聚合** | Go | 高并发读取 + 内存聚合 + 定时刷新，Go 写这类服务轻量高效 |
| **上传处理** | Go | 图片压缩/缩略图/元数据提取，内存控制好，部署简单 |
| **运营分析脚本** | Python | 离线数据分析、留存报表、热帖趋势，pandas/matplotlib 现成 |

```
新增：
  Go cyxz-feed（推荐流聚合 / 热榜计算 / 关注流扇出）
  Go cyxz-media（图片处理 / 缩略图 / 格式转换）
  Python scripts/（离线分析脚本）
```

**当前状态**：

- 推荐流：未实现，`GET /post/following` 为拉模式时间线
- 上传处理：`cyxz-upload` 用 Java + MinIO，未做图片压缩/缩略图
- 运营分析：未实现

### 第四阶段：i18n 国际化（长期）

**触发条件**：项目面向海外用户或需要多语言支持时。

**后端方案**：

- Spring `MessageSource` + `LocaleResolver`
- `Accept-Language` 请求头解析
- 错误码 → 多语言消息映射文件 `messages_zh.properties` / `messages_en.properties`
- 数据库用户表增加 `locale` 字段记录偏好语言

**前端方案**：

- `vue-i18n` + JSON 语言包
- 语言切换持久化到 localStorage
- 路由懒加载语言包，避免首屏过大

**当前不做的理由**：

- 项目定位为中文二次元社区，目标用户明确
- i18n 会增加文案维护成本，需配套翻译流程
- 优先级低于核心功能完善

## 五、每个模块不做什么

| 模块 | 只做 | 不做 |
|---|---|---|
| Python AI（已实现） | 文本/图片审核计算 | 存数据、业务流转、权限控制 |
| Go IM（规划） | 建连/私聊/圈聊/消息广播/在线状态/未读 | 好友关系、用户信息、圈子业务逻辑 |
| Go 推送（规划） | SSE/WS 推送通道 | 消息模板、通知策略、业务触发 |
| Go Feed（规划） | 聚合/排序/缓存刷新 | 推荐算法模型训练 |
| Go Media（规划） | 压缩/缩图/格式转换 | 文件存储、权限、CDN |

## 六、实施建议

1. **同一时间只做一个语言模块**，做稳一个再加下一个
2. **每个新模块先独立跑通 HTTP 调用链路**，再考虑优化通信方式
3. **Go 和 Python 服务同样注册到 Nacos**，统一服务发现
4. **新模块出问题不能拖垮主业务**，所有跨语言调用必须有超时降级
5. **数据库优先共享**（同一 MySQL 实例不同表），不走分布式事务

## 七、技术亮点（简历视角）

1. **跨语言架构落地**：Java 主业务 + Python AI 服务，HTTP 解耦，各自用最擅长的语言
2. **fail-closed 降级**：跨语言调用失败时主业务安全降级，不拖垮核心流程
3. **职责单一**：Python AI 服务纯函数化，不碰 DB/缓存/MQ，易测试易部署
4. **演进路径清晰**：从单语言 → 补 Python AI → 补 Go IM → 补 Go 工程效率，每步都有明确触发条件
5. **不做过度设计**：当前 Java WebSocket 单实例够用就不急着迁 Go，等规模到了再演进
