# 权限缓存设计

## 一、架构原则

| 职责 | 说明 |
|---|---|
| JWT | 仅存 userId / jti / iat / exp，不存角色和权限码 |
| Gateway | 验签 + 注入 X-User-Id，不查权限 |
| Security Filter | 读 userId → 加载权限 → 构造 SecurityContext |
| Redis | 权限查询结果缓存，TTL 对齐 JWT 过期时间 |
| DB | 权限最终权威来源，Redis 不可用时兜底 |

权限变更实时生效链路：

```text
DB 事务提交 → 删除对应 Redis Key → 下次请求 DB 重建缓存
```

## 二、Redis Key 设计

### 2.1 全局权限缓存

```text
Key:   auth:global:{userId}
Type:  Hash
TTL:   对齐 JWT 过期时间
```

字段：

```text
roles       → SITE_OWNER,PLATFORM_ADMIN
perms       → circle:admin:list,circle:status:update,post:review:list,...
```

写入时机（Cache-Aside 旁观策略）：

- 请求时未命中 → 查 DB → 回写（各业务服务安全过滤器）

删除时机：

- 用户全局角色变更（assignRole / removeRole，circleId=0 时）
- 角色权限配置变更（查 DB 找出受影响用户 → 逐个删 key，见 2.3）

### 2.2 圈子权限缓存

```text
Key:   auth:circle:{userId}:{circleId}
Type:  Hash
TTL:   对齐 JWT 过期时间
```

字段：

```text
perms       → circle:section:manage,circle:post:review,circle:post:delete,...
```

写入时机：

- 请求时未命中 → 查 DB → 回写（CirclePermissionEvaluator）

删除时机：

- 用户圈子角色变更（任命管理员 / 撤销管理员 / 踢出成员）
- 角色权限配置变更（查 DB 找出受影响用户 → 逐个删 key，见 2.3）

### 2.3 角色权限配置变更失效

角色权限配置变更（如给 CIRCLE_ADMIN 增减权限码）时，采用 Cache-Aside 旁路逐个删 key：

```text
1. 查 DB 找出拥有该角色的所有用户 ID 及对应 circle_id
   SELECT user_id, circle_id FROM sys_user_role WHERE role_id = #{roleId}

2. 遍历结果集，按 circle_id 区分删除：
   circle_id = 0 → DEL auth:global:{userId}
   circle_id > 0 → DEL auth:circle:{userId}:{circleId}
```

### 2.4 缓存失效矩阵

| 操作 | 失效动作 |
|---|---|
| 用户全局角色变更 | `DEL auth:global:{userId}` |
| 任命圈子管理员 | `DEL auth:circle:{userId}:{circleId}` |
| 撤销圈子管理员 | `DEL auth:circle:{userId}:{circleId}` |
| 踢出成员 | `DEL auth:circle:{userId}:{circleId}` |
| 修改角色权限配置 | 查 DB 找用户 → 逐个 `DEL auth:global:{userId}`（+圈子 key） |
| 用户登出 | `DEL auth:global:{userId}` |

## 三、Redis 故障降级策略

```
查 Redis
├── 命中 → 使用缓存权限
├── 未命中 → 查 DB → 回写 Redis → 返回
├── Redis 异常 → 查 DB → 返回（不写缓存）
└── Redis + DB 都异常 → 拒绝请求（不放行）
```

**安全底线**：Redis 故障不能导致权限绕过。

## 四、SQL 查询

### 4.1 查询用户全局角色和权限

```sql
-- 查询用户全局角色（circle_id = 0）
SELECT
    r.code AS role_code,
    r.label AS role_label
FROM cyxz_auth.sys_user_role ur
JOIN cyxz_auth.sys_role r ON ur.role_id = r.id
WHERE ur.user_id = #{userId}
  AND ur.circle_id = 0;

-- 查询全局角色对应的权限码
SELECT DISTINCT p.code
FROM cyxz_auth.sys_user_role ur
JOIN cyxz_auth.sys_role_permission rp ON rp.role_id = ur.role_id
JOIN cyxz_auth.sys_permission p ON p.id = rp.permission_id
WHERE ur.user_id = #{userId}
  AND ur.circle_id = 0;
```

### 4.2 查询用户在圈子中的角色

```sql
SELECT role_id
FROM cyxz_auth.sys_user_role
WHERE user_id = #{userId}
  AND circle_id = #{circleId};
```

### 4.3 查询角色对应的权限码

```sql
SELECT DISTINCT p.code
FROM cyxz_auth.sys_role_permission rp
JOIN cyxz_auth.sys_permission p ON p.id = rp.permission_id
WHERE rp.role_id IN
    <foreach item="id" collection="roleIds" open="(" separator="," close=")">
        #{id}
    </foreach>;
```

### 4.4 查询拥有指定角色的用户（角色权限配置变更时失效缓存用）

```sql
SELECT user_id, circle_id
FROM cyxz_auth.sys_user_role
WHERE role_id = #{roleId};
```

## 五、Java 接口抽象

### 5.1 GlobalPermissionProvider

```java
package com.cyxz.common.security;

import java.util.Set;

/**
 * 全局权限提供者
 * <p>负责从 Redis/DB 加载用户的全局角色和权限码。
 */
public interface GlobalPermissionProvider {

    /**
     * 获取用户全局角色 code 集合
     *
     * @param userId 用户 ID
     * @return 角色 code 集合，如 [SITE_OWNER, PLATFORM_ADMIN]
     */
    Set<String> getRoles(Long userId);

    /**
     * 获取用户全局权限码集合
     *
     * @param userId 用户 ID
     * @return 权限码集合，如 [post:review:list, post:admin:delete]
     */
    Set<String> getPermissions(Long userId);
}
```

### 5.2 CirclePermissionEvaluator（改造后）

```java
// 查询链路
hasAuthority(permissionCode, circleId)
  ├── 未登录 → false
  ├── circleId 为空 → false
  ├── isGlobalAdmin() → true（短路）
  ├── Redis GET auth:circle:{userId}:{circleId}
  │     ├── 命中 → 判断权限码
  │     └── 未命中 / Redis 异常 → 查 DB
  ├── DB 查询角色 + 权限码
  ├── Redis 回写（异步或同步，失败忽略）
  └── 返回判断结果
```

## 六、SecurityContext 构造逻辑

```java
// DynamicAuthorityFilter 或 HeaderAuthenticationFilter 中

String userIdHeader = request.getHeader("X-User-Id");
Long userId = Long.valueOf(userIdHeader);

// 加载全局角色和权限
Set<String> roles = globalPermissionProvider.getRoles(userId);
Set<String> permissions = globalPermissionProvider.getPermissions(userId);

// 构造 GrantedAuthority
List<GrantedAuthority> authorities = new ArrayList<>();
roles.forEach(r -> authorities.add(new SimpleGrantedAuthority("ROLE_" + r)));
permissions.forEach(p -> authorities.add(new SimpleGrantedAuthority(p)));

// 写入 SecurityContext
Authentication auth = new UsernamePasswordAuthenticationToken(userId, null, authorities);
SecurityContextHolder.getContext().setAuthentication(auth);
```

构造完成后 Controller 可直接使用：

```java
@PreAuthorize("hasAuthority('post:admin:list')")
@PreAuthorize("@circlePerm.hasAuthority('circle:post:review', #circleId)")
```

## 七、依赖关系

```text
cyxz-security (公共安全模块)
  └── GlobalPermissionProvider (接口)
  └── CirclePermissionEvaluator (圈子权限)
  └── DynamicAuthorityFilter (动态权限过滤器)
  └── 依赖 cyxz-common (RedisTemplate)

需要完整权限的服务（启用 DynamicAuthorityFilter）：
  ├── cyxz-auth
  ├── cyxz-circle
  ├── cyxz-post
  └── cyxz-upload

仅需身份识别的服务（不加载权限）：
  ├── cyxz-user
  ├── cyxz-comment
  ├── cyxz-message
  └── cyxz-search
```
