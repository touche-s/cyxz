# 圈子化设计

> 圈子是次元小站的内容组织核心。本文档分已实现和规划两部分，已实现内容均基于代码核对。

## 设计定位

走"深而纯"路线，避免泛化：**圈子归属 > 算法分发，身份认同 > 流量数据，圈内秩序 > 全站大一统**。

内容维度拆分：

| 维度 | 作用 | 用户感知 |
|---|---|---|
| 创作类型 | 决定编辑器与展示形态 | 图文 / 长文 |
| 圈子 | 内容归属社区 | 原神讨论圈 / MyGO 同好圈 |
| 圈内板块 | 圈内主题分区 | 同人创作 / 作品讨论 / 攻略考据 |
| 标签 | 补充细节语义 | 角色 / 作品 / 风格（可选） |

不存在"全站大分类"作为主结构。一篇帖子的数据语义为：`圈子 → 板块 → 标签`，例如 `原神圈 → 同人创作 → 芙宁娜/同人图`。

差异化定位：

| | B 站 | 次元小站 |
|---|---|---|
| 内容分发 | 算法推荐流 | 关注流 + 圈子流 |
| 内容类型 | 泛化（生活区挤占 ACG） | 纯 ACG（不做短视频/直播间） |
| 社区归属 | 弱（UP 主粉丝关系） | 强（圈子成员身份） |
| 分类方式 | 全站统一分区 | 圈内板块 + 标签 |

## 一、已实现

> 基于 `cyxz-circle` 与 `cyxz-post` 模块代码核对。

### 1. 圈子 CRUD 与查询

| 接口 | 说明 |
|---|---|
| `GET /circle/list` | 全量启用圈子列表，按 `sort_order` 升序 |
| `GET /circle/{circleId}` | 圈子详情，返回当前用户是否已加入 |
| `GET /circle/hot` | 热门圈子分页，按 `member_count` 降序 |
| `GET /circle/joined` | 当前用户已加入的圈子 |
| `POST /circle` | 管理员建圈，自动生成 slug，并初始化默认板块 |
| `PUT /circle/{circleId}` | 管理员更新圈子资料（name/intro/avatar/cover） |
| `DELETE /circle/{circleId}` | 管理员逻辑删除圈子（status 置为 DELETED） |

### 2. 圈子成员

- `POST /circle/{circleId}/join` 加入圈子：`upsert` 写入成员关系，原子递增 `member_count`，支持退出后恢复。
- `DELETE /circle/{circleId}/join` 退出圈子：软删除成员（status 置为非活跃），原子递减 `member_count`。

### 3. 板块模板系统

板块采用"模板 + 启用关系"两层模型，保证全站命名一致：

- `SectionTemplateController`（`/admin/section-template`）提供模板的增删改查，仅管理员可操作。
- 模板字段 `applicable_type` 区分适用创作类型：`ALL`（全部）/ `NORMAL`（图文）/ `ARTICLE`（长文）。

### 4. 圈子板块配置

- `GET /circle/{circleId}/sections` 查询圈子已启用板块（含模板名称、是否默认、排序），发布页与圈子详情页共用。
- `PUT /circle/{circleId}/sections` 管理员全量替换圈子板块配置（先删后插）。
- 创建圈子时自动调用 `initDefaultSections`：取所有 `ALL` 类型模板初始化，首个设为默认板块。
- 无默认板块时通过 `fallbackDefault` 兜底取首个 `ALL` 模板。
- 内部接口 `validateSection` / `batchGetSectionNames` 供 post 模块 Feign 调用，校验板块归属并批量取名称。

### 5. 发布权限校验

- `GET /circle/internal/{circleId}/publishable` 校验：圈子存在 + 圈子启用 + 用户已加入，三者均满足才允许发布。

### 6. 帖子查询与排序（post 模块）

- `GET /post/list` 支持 `circleId + sectionId + sortBy` 组合筛选。
- `sortBy` 白名单：`latest`（按 `create_time DESC`）/ `hot`（按 `likes → comments → collections → views → create_time` 多级排序），非法值降级为 `latest`。
- 圈子详情页与全站列表复用同一排序能力。

### 7. 圈子计数同步

- `CircleMapper` 提供原子增减（`updatePostCount` / `updateMemberCount`，使用 `GREATEST(...,0)` 防负）与覆盖（`setPostCount` / `setMemberCount`）。
- `CircleCountFlushTask` + `CircleCountFlushService` 定时通过 `GET /post/internal/batch-circle-post-count` 批量拉取各圈子已发布帖子数并刷库。

### 8. 帖子生命周期（post 模块）

发布、草稿、更新、逻辑删除、回收站物理删除（级联清理评论/点赞/收藏）、点赞/收藏（幂等）、浏览记录（Redis 去重 + 定时刷库）、置顶/取消置顶、批量操作、管理员审核（待审/通过/拒绝）、敏感词检测均已具备。

## 二、规划中

> 从源文档提取尚未在代码中实现的设计，标注"待实现"。

### 1. 圈子大类与搜索（待实现）

- 在 `circle` 表与 `CircleVO` 增加 `type` 字段（如 `游戏 / 动漫 / 虚拟偶像 / 原创`），用于圈子广场大类筛选。**当前 `CirclePO` 无此字段，不能在前端硬编码作品名归类。**
- 圈子搜索后端接口：当前建议第一版前端按名称/slug/intro 过滤，后续替换为服务端搜索。

### 2. 首页"我的圈子"动态摘要（待实现）

- 圈子卡片展示"今日新增 X 篇"或"最近更新于 XX"。
- 或在"我的圈子"下展示每个圈子最新一篇帖子预览。
- 仅展示有新内容的已加入圈子，降低噪音。先验证回访意愿，不做复杂未读系统。

### 3. 发布页体验优化（待实现）

- 从圈内发布时 `circleId` 保持预选且不被意外清空。
- 已加入圈子在选择器中排序靠前。
- 选中作品圈后，板块区域标题改为"发布板块"，强化"圈子内板块"语义。
- 保持 `circleId` 与 `sectionId` 均为发布必填。

### 4. 内容治理闭环（待实现）

公开推广前必须具备的安全底线（与圈子功能解耦）：

- 帖子/评论举报入口与管理端举报记录查看。
- 明确的社区规范页面。
- 举报、删除、审核操作保留审计日志。
- 基础敏感词拦截已有（`SensitiveWordService`），需补充命中提示与治理流程。

### 5. 圈子申请与官方审核建圈（待实现）

当前仅管理员直接建圈。后续增加"申请新增圈子"入口，由管理员审核创建官方圈，**不开放用户自建圈**。

### 6. 轻运营身份体系（待实现）

待圈子活跃度上升后再评估，不在当前阶段引入：

- 圈子协作者 / 圈子主持人 / 圈内活动发起者。
- 圈主体系、复杂成员权限、私有分区映射。

### 7. 圈内内容运营（待实现）

- 圈内精华、官方置顶（区别于当前用户级置顶）、活动页。

### 8. 标签体系与作品专题（待实现）

- 作品/IP 标签与角色标签结构化（当前为自由标签）。
- 作品专题页。
- 全站按分类聚合跨圈帖子的能力。

### 9. 圈内等级与门槛（待实现）

- 圈内等级、签到、积分、勋章体系。
- 入圈测试、发帖等级门槛（用于内容过滤）。

### 10. 推荐与 AI 辅助（待实现）

- 个性化推荐算法、用户兴趣画像（当前"推荐"为综合热门或运营精选，非算法）。
- AI 辅助标签建议、圈内新手问答、热帖摘要。
- AI 审核辅助，但必须保留人工审核与举报复核链路。

## 三、数据模型

> 基于 `cyxz-circle` 模块 Entity 类。所有表继承 `BaseEntity`，含 `create_time`、`update_time`（由 `MyMetaObjectHandler` 自动填充）。

### 1. `circle` 圈子表

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long | 主键 |
| name | String | 圈子名称 |
| slug | String | URL 友好标识，建圈时由 name 自动生成 |
| intro | String | 圈子简介 |
| avatar | String | 圈子头像 |
| cover | String | 圈子封面 |
| status | Integer | 状态：1=启用，0=禁用，DELETED=逻辑删除 |
| sort_order | Integer | 排序值，越小越靠前 |
| post_count | Integer | 帖子数（定时刷库同步） |
| member_count | Integer | 成员数（加入/退出原子增减） |
| create_time / update_time | LocalDateTime | 审计字段 |

### 2. `circle_member` 圈子成员表

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long | 主键 |
| circle_id | Long | 圈子 ID |
| user_id | Long | 用户 ID |
| status | Integer | 成员状态：1=活跃，0=已退出（支持恢复） |
| create_time / update_time | LocalDateTime | 审计字段 |

### 3. `section_template` 板块模板表

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long | 主键 |
| name | String | 板块名称，如"同人创作""作品讨论" |
| applicable_type | String | 适用创作类型：`ALL` / `NORMAL` / `ARTICLE` |
| description | String | 模板描述 |
| sort_order | Integer | 排序值 |
| create_time / update_time | LocalDateTime | 审计字段 |

### 4. `circle_section` 圈子板块关联表

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long | 主键 |
| circle_id | Long | 圈子 ID |
| template_id | Long | 关联的板块模板 ID |
| is_default | Integer | 是否默认板块：1=是，0=否（发帖时预填） |
| sort_order | Integer | 圈子内排序 |
| status | Integer | 状态：1=启用，0=禁用 |
| create_time / update_time | LocalDateTime | 审计字段 |

### 5. `post` 表圈子相关字段

基于 `PostController` 接口反推，`post` 表已包含：

- `circle_id`：帖子所属圈子
- `section_id`：帖子所属板块（指向 `circle_section.id`）

发布时 post 模块通过 Feign 调用 `validateSection` 校验 `sectionId` 归属 `circleId` 且已启用。

## 四、演进路线

### 近期：补齐圈子发现与治理闭环

1. `circle.type` 大类字段落地，圈子广场支持大类筛选。
2. 圈子搜索从前端过滤升级为服务端接口。
3. 首页"我的圈子"动态摘要，验证回访。
4. 发布页圈内预选稳定性与已加入圈子排序优化。
5. 举报入口、举报记录、审计日志、社区规范页组成最小治理闭环。

### 中期：内容运营与官方建圈

1. 圈子申请与官方审核建圈流程，替代管理员直接建圈。
2. 圈内精华、官方置顶、活动页。
3. 作品/IP 标签与角色标签结构化，作品专题页。
4. 轻运营身份（协作者/主持人）按需引入。

### 远期：身份体系与智能化

1. 圈内等级、签到、积分、勋章、入圈测试、发帖门槛。
2. 个性化推荐算法与用户兴趣画像。
3. AI 辅助标签建议、新手问答、热帖摘要、AI 审核辅助（保留人工复核）。

### 冷启动原则

不在首页同等曝光所有圈子。初期挑选 5～8 个重点圈，确保每个圈有清晰封面/简介、多类型示例帖子、至少两个板块有内容、有持续更新的体验用户。建议优先主推：原神、崩坏：星穹铁道、明日方舟、MyGO、孤独摇滚、VOCALOID、原创圈。新圈子不一次创建过多。
