# 产品设计

> 次元小站——二次元垂直兴趣社区。本文档分已实现和规划两部分。
> 已实现部分基于代码核对，规划部分整合自 4 份产品设计文档（去掉过时内容、合并去重）。

---

## 一、已实现

当前产品已完成内容社区的核心闭环：以圈子为组织单元，覆盖认证、发布、互动、评论、消息、搜索、AI 审核、上传等能力。后端拆分为 10 个微服务（auth / gateway / post / user / comment / circle / message / search / upload / common），另有 Python FastAPI 编写的 AI 审核服务，前端为 Vue3 单页应用。

### 1.1 认证与网关

- **注册 / 登录 / 登出 / 改密 / 刷新 Token**：账号密码 + 验证码校验，登录返回 JWT；登出将 Token 加入 Redis 黑名单；支持旧 Token 换新。
- **网关鉴权**：Spring Cloud Gateway 统一转发路由、CORS、JWT 校验，并通过 `X-User-Id` 信任头向下注入用户身份；管理员身份由 `@AdminUser` 注解解析。
- **验证码**：独立 Captcha 接口，注册登录前置校验。
- **用户管理**：管理员侧用户查询/管理接口已具备（`UserAdminController`）。

### 1.2 帖子与内容发布

帖子状态机：`DRAFT(0) → PENDING(1) → APPROVED(2) / REJECTED(3) → DELETED(4)`，所有状态码统一收敛到 `PostStatus` 常量。

- **发布与草稿**：支持图文帖、长文，草稿独立保存；编辑草稿后发布同样会触发 AI 审核。
- **删除**：逻辑删除进回收站；永久删除做级联清理（评论、点赞、收藏）。
- **列表与详情**：按板块 / 圈子筛选，支持 latest / hot 排序；详情含作者信息与板块名。
- **互动**：点赞、收藏、浏览记录均幂等，Redis 增量计数 + 定时刷库。
- **关注动态流**：`GET /post/following` 拉模式实现——查关注作者 ID 列表 → 分页查其已发布帖子。
- **创作者中心**：数据统计（总浏览 / 点赞 / 收藏）、仪表盘（概览 + 月度趋势 + 板块分布 + Top 作品）、今日新增互动、作品排行榜、收到的点赞列表。
- **管理**：置顶 / 取消置顶、批量操作（发布 / 删除等）。
- **审核接口**：管理员侧待审核列表、通过、拒绝。
- **敏感词**：当前为暴力匹配（O(N×M)），发布前预检；用户可手动调用 `/post/check-sensitive` 自检。规划引入 AC 自动机优化。
- **AI 审核**：Python FastAPI 异步调用，文本审核（`/review`）+ 图片审核（`/review/image`），fail-closed 策略；审核结果由 `PostServiceImpl` 编排（更新状态 + 发通知）。事务提交后再派发异步任务，避免读到旧状态。
- **MySQL 帖子搜索**：`/post/search` 标题 + 正文模糊匹配（作为 ES 不可用时的兜底）。

### 1.3 圈子

- **基础能力**：圈子列表、详情、热门圈子分页（按成员数降序）、我加入的圈子、加入 / 退出。
- **管理**：管理员创建 / 更新 / 删除圈子。
- **板块**：圈子下可配置多个板块（如剧情讨论 / 攻略 / 同人创作 / Cosplay），发帖时选择板块；板块模板可复用（`SectionTemplateController`）。
- **发布权限**：发帖前通过 Feign 同步校验 `publishable`（圈子启用 + 已加入），覆盖创建、草稿转发布、批量发布。
- **帖子数同步**：圈子服务定时（60s）通过 Feign 批量查 `status=2` 帖子数 → 覆盖写入 `circle.post_count`，无增量、无重复计数风险。
- **内部接口**：批量查圈子名、批量查板块名、校验板块归属。

### 1.4 用户与关注

- **资料**：查询 / 修改个人资料，注册时由 auth 服务 Feign 调用初始化默认资料；进入个人空间时按需兜底创建。
- **关注关系**：关注 / 取关、是否关注、是否互相关注（私信入口判断）、关注列表、粉丝列表、关注数 / 粉丝数 / 新粉丝数。
- **个人空间**：他人作品 Tab、收藏 Tab；批量资料查询供 post / comment 服务聚合作者信息。

### 1.5 评论

- **发表 / 删除**：评论支持嵌套回复，逻辑删除。
- **列表**：顶级评论分页 + 子回复分页（默认带首页 5 条）。
- **互动**：评论点赞 / 取消点赞（幂等）。
- **管理**：收到的评论列表（自己帖子被评论）、评论管理页（按帖子筛选、正序 / 倒序）。
- **内部接口**：按帖子级联删除、今日评论数（供创作者中心工作台）。
- **计数同步**：定时刷库帖子评论数。

### 1.6 消息通知

- **通知类型**：5 类互动通知 + 2 类系统通知——`POST_LIKED` / `POST_COMMENTED` / `COMMENT_REPLIED` / `POST_COLLECTED` / `USER_FOLLOWED`，以及 `POST_APPROVED` / `POST_REJECTED`。
- **能力**：通知列表（按类型筛选）、未读数、单条已读、全部已读。
- **闭环**：RabbitMQ 异步事件消费 + 唯一索引去重幂等（关注通知填充 `target_id` 避免 NULL 失效）。
- **私信**：会话列表、消息收发、WebSocket 实时推送、互相关注才能发起私信。

### 1.7 搜索

- **ES 全文检索**：`/search/post` 标题 + 正文 matches 查询，支持高亮、圈子过滤、hot / latest 排序、分页（size 上限 50）。
- **数据同步**：`PostEsSyncConsumer` 消费 RabbitMQ 同步事件，帖子发布 / 更新 / 删除时索引同步。
- **全量重建**：`EsFullSyncRunner` 启动时按需全量重建索引。

### 1.8 上传

- **MinIO 对象存储**：头像、帖子图片、圈子资源（头像 / 封面）上传。
- **安全**：文件类型 / 大小校验；删除时校验路径归属（`avatar/{userId}/`、`post/image/{userId}/`）防止越权删除他人文件。
- **头像历史**：保留用户历史头像列表。

### 1.9 管理后台

后端 admin 接口已分散沉淀在各 Controller（`@AdminUser` 鉴权 + `/admin/**` 路径），前端 `AdminView.vue` 已具备基础页面。当前覆盖：帖子审核、圈子管理、用户管理。举报工单、操作日志等待补全。

## 二、规划中

> 以下设计来自 4 份产品文档，**均未实现**，标注「待实现」。已剔除过时设想（如「搜索升级到 ES」已完成、转为已实现项）。

### 2.1 IP / 作品维度组织（待实现）

二次元社区内容天然围绕作品 / 角色 / CP / 阵营组织，目前仅有圈子 + 板块两层，缺作品层。

- **作品 / IP 标签体系**：发帖时除圈子 + 板块外，允许选 0~3 个作品标签（原神 / 崩铁 / 孤独摇滚）、0~3 个角色标签、1 个内容类型（安利 / 攻略 / 同人图 / COS / 考据 / 讨论）。后期演进为结构化标签库，支持按角色追踪、按作品聚合。
- **IP / 作品资料页**：聚合相关圈子、热门帖子、角色信息、官方资讯；需新建 `cyxz-ip` 模块；冷启动期可由管理员后台维护少量头部作品资料，避免大规模爬虫合规风险。
- **结构化发布表单**：按内容类型提供不同发帖结构（安利帖需作品 + 推荐理由 + 配图；同人创作需作品 + 角色 + 图集 + 创作说明）；通过 `post_type`（图文分享 / 长文考据 / 攻略清单 / 投票 / 作品集 / 活动投稿 / 约稿）统一扩展框架，不硬塞字段。

### 2.2 二次元内容形态（待实现）

- **剧透管理**：帖子标注剧透等级（正常 / 含剧透 / 严重剧透）+ 剧透范围（如「原神 5.3 主线」）；列表中模糊封面 + 警告标签，详情页二次确认展开。
- **创作系列 / 作品集**：面向创作者的「连载」单元，支持漫画连载、同人小说章节、攻略系列、Cos 图集、画师作品集；用户可追更、每话单独评论、收到更新通知。
- **同担标签**：个人资料展示「我推的角色 / 作品 / 常驻圈」，帖子评论处展示共同标签；仅做表达，不做匹配算法。
- **帖子投票**：一帖一投票，2~6 选项单选，可设截止时间，结果可视化；归 post 领域不拆服务。

### 2.3 圈子机制深化（待实现）

当前圈子只是帖子筛选页，缺归属感。

- **圈子公示信息**：成员总数 + 今日新增讨论、圈子公告（圈主可编辑）、本周话题 / 置顶活动帖、活跃圈友小榜。
- **圈子身份**：加入即「圈友」；每种圈子可自定义称呼（旅行者 / 开拓者 / 舰长）；展示圈内累计发帖 / 评论 / 被赞数；新圈友加入提示。
- **圈内活动**：置顶活动帖 + 截止时间、活动专属标签、参与帖聚合展示。活动类型：每周图楼、新番完结讨论楼、角色生日企划、Cos 招募、同人接龙、版本专题。
- **圈子分层运营**：S 级（官方共建，头部 IP，官方资料库 + 资源倾斜）/ A 级（社区自治，圈主自主运营 + 平台工具）/ B 级（长尾兴趣，降门槛 + 跨圈曝光）。当前仅具备 A / B 级基础能力。

### 2.4 社区氛围与治理（待实现）

- **举报与工单**：帖子 / 评论举报 → 后台审核流 → 处理时间线（隐藏 / 驳回 / 删除）+ 审计日志；用户反馈工单（功能建议 / Bug / 内容举报）。
- **新用户引导**：注册后选 3 个兴趣圈子 → 生成初始首页流；初期规则驱动，不依赖推荐算法。
- **审核反馈的人味**：以拟人化文案替代冷冰冰的「审核失败」（含剧透 → 提示补充剧透范围；涉嫌引战 → 提示调整措辞）。
- **编辑精选**：每日精选、本周创作、新星创作者；后台人工挑选，首页小区域展示；冷启动期替代推荐算法。
- **文案语境**：圈友 / 同好、入坑、本圈热议、追更、收藏册、本周企划、板块、次元公约等二次元语境表达；系统级操作（保存 / 删除 / 改密）保持清晰不玩梗。

### 2.5 商业化（待实现，仅设计不落地）

采用「低摩擦间接收入优先 → 直接交易收入」的梯度，外链导购为主，平台不碰资金流。

- **数字装扮**：主题色 / 挂件 / 进场特效，平台自营，低摩擦变现。
- **衍生品橱窗 / 谷子展示柜**：T1 引流款（谷子 / 贴纸 / 数字表情包 ¥1-30）→ T2 主力款（同人本 / Cos 包 ¥20-80）→ T3 锚定款（限定周边 / 签约内容 ¥100-500）；导购外链模式，平台不参与交易；帖子底部「同款周边」推荐卡联动。
- **创作者激励**：优质内容 → 积分 → 兑换权益 / 实物。
- **轻量广告**：圈子相关 CPC，仅出现在圈子广场侧栏，每用户每日最多 3 次。
- **付费内容**：创作者付费长文 / 教程，平台抽成（成熟期）。
- **商业化红线**：不插信息流广告；不付费解锁基础功能；不卖推荐位；不参与同人交易；广告频次限制；创作者利益优先。

### 2.6 版权合规（待实现，需在商业化前落地）

- **平台定位**：用户协议明确为 ISP（信息存储空间），适用避风港原则；侵权通知-删除流程 48h 响应；重复侵权 3 次封禁发布。
- **内容分层标注**：发布时强制选「原创 / 二创·非营利 / 二创·同人本 / 转载」；转载必填来源链接；二创内容自动添加原作声明。
- **同人衍生品交易隔离**：允许官方授权周边 + 原创设计周边；限制同人周边限量售卖（导购外链）；禁止未授权批量生产、冒充官方、平台直接参与同人交易。
- **技术风控**：图片感知哈希（pHash）+ ES 向量近邻检索防盗图；24h 跨用户重复发布标记；侵权次数计数；高风险 IP 词库加强审核。
- **AI 内容标记**：AI 辅助创作内容标记「AI 辅助」，不参与衍生品售卖；AI 服务做算法备案。
- **未成年人保护**：注册实名；未成年用户不可访问衍生品交易；敏感内容折叠。

### 2.7 工程与运营支撑（待实现）

- **统一任务编排 cyxz-job**：凌晨对账调用各服务内部接口（圈子帖子数 / 成员数 / 互动数 / 评论点赞数），任务执行记录 + 失败重试 + 管理端手动执行；后期可接入 XXL-JOB / PowerJob。
- **审计日志**：管理员操作日志、关键用户行为记录（操作者 / 对象 / 前后状态 / 时间）。
- **可观测性**：健康检查、接口耗时与错误统计、MQ 死信监控、Redis Key 积压观测。
- **ES 同步死信队列**：当前 ES 同步缺死信，不可用时消息会丢失，需参照通知服务补上。
- **图片治理**：上传任务状态、压缩与缩略图、引用计数、孤儿文件清理。
- **搜索能力扩展**：当前仅支持帖子 ES 搜索，规划扩展为帖子 / 圈子 / 用户 / 标签统一搜索，搜索结果分 Tab 展示。
- **多端覆盖**：移动端适配 / 小程序（规模化阶段）。

## 三、产品定位与垂直化思考

### 3.1 一句话定位

> 以圈子为基本组织单元、以 IP / 作品为内容锚点、以创作者与同好关系为纽带的二次元垂直内容社区。

更聚焦的表达：**一个以图文安利、同人创作、作品讨论为核心，面向 ACG 爱好者与内容创作者的垂直内容社区**。

### 3.2 与泛社区的关键区别

| 维度 | 泛社区（B 站 / 贴吧 / 小红书） | 次元小站 |
|------|------------------------------|----------|
| 首页 | 全站帖子瀑布流 | 我的圈子动态 |
| 组织 | 时间 / 热度 / 通用分类 | 圈子 + 板块 + 作品 |
| 内容 | 什么都能发 | 天然围绕 ACG 内容表达 |
| 用户身份 | 用户 | 圈友 / 同好 |
| 驱动 | 算法推荐 | 圈子归属回访 |
| 形态 | 视频流 / 泛内容 | 纯图文 + 长文 |

**不做的事**：不做全屏沉浸视频流（可支持视频帖，但不以视频消费时长为核心指标）；不做纯算法推荐首页（次元街保留为逛街入口，不取代圈子主页）；不做泛社交广场。

### 3.3 垂直化的三层含义

1. **内容主题垂直**：集中在动漫、游戏、同人创作、角色安利、追番感想、世界观考据、COS / 摄影、周边开箱、剪辑分享，而非泛生活 / 泛情绪。
2. **兴趣组织方式垂直**：按作品 / IP / 角色 / CP / 阵营 / 同人类型组织，而非按时间 + 通用分类。用户兴趣点是「我想看原神的内容」「我想看芙宁娜的创作」，不是「我想看个帖子」。
3. **社区氛围垂直**：用户在意内容是否有明确主题、能否快速找到同好、是否有持续更新的创作者、能否沉淀作品向内容而非水帖。

### 3.4 当前差距

技术能力已具备，但产品语义还不够垂直：

- **缺作品 / IP / 角色维度**：内容只有标题 + 正文 + 圈子，未关联作品 / 角色 / 内容类型 → 难以聚合与筛选。
- **关系网络未完全活起来**：关注动态流虽已实现，但消息通知尚未形成完整回访闭环（如圈内活动通知、追更更新通知）。
- **缺优质内容沉淀机制**：社区页仍偏时间流，缺热门作品 / 热门标签 / 本周安利 / 最新同人创作等兴趣聚合入口。

### 3.5 社区分层认知

```
L1 消费者（70-74%）→ 低门槛浏览，新用户引导选圈子         → 已实现
L2 参与者（20%）   → 互动闭环，通知 + 关注动态             → 已实现
L3 贡献者（5-8%）  → 社区地位，圈内等级 + 称号              → 仅创作者中心数据面板已实现
L4 创作者（<1-2%） → 影响力 + 变现，精选推荐 + 创作挑战      → 待实现
```

### 3.6 文案语境

二次元味不只靠粉紫色 UI，更靠产品文案语境：圈友 / 同好、入坑、本圈热议 / 今日高能、追更、收藏册、本周企划、板块、次元公约。系统级操作（保存 / 删除 / 改密）保持清晰不玩梗。

一句话价值主张：

> 让 ACG 用户更容易发布内容、发现同好、沉淀表达，并围绕作品与创作者形成持续互动。

## 四、演进路线

按优先级分四阶段，已完成的不再列入。

### Phase 1 — 基础稳固（当前进行中）

| 优先级 | 任务 |
|--------|------|
| P0 | P0 安全修复：网关信任头剥离、状态码统一、AI fail-closed、内部接口 `/internal/**` 鉴权 |
| P0 | 管理后台补全：举报工单、操作日志、审计日志 |
| P0 | ES 同步死信队列补齐 |
| P1 | 用户协议 v1（版权声明 / 避风港 / 二创声明） |
| 中 | 内测准备：邀请 50-100 种子用户 |

### Phase 2 — 社区深化

| 优先级 | 任务 |
|--------|------|
