# 次元小站 后续规划

> 本文档分已实现和规划两部分，已实现内容均基于代码核对。

## 设计定位

次元小站定位为二次元创作社区，核心价值是 **圈子化创作 + 互动反馈 + 内容安全**。后续规划围绕三条主线展开：

- **主线 A（产品定位）**：二次元创作社区 — 圈子 → 主题活动 → 作品系列 → 投票 → 收藏夹 → 约稿
- **主线 B（上线意识）**：真实社区治理 — 反馈工单 → 举报 → 审核后台 → 审计日志 → 圈子管理
- **主线 C（工程架构）**：技术深度 — 微服务拆分 → Redis 跨服务计数 → MQ 异步通知 → 任务编排 → CI/CD → 可观测性

推荐 A + B 并重，C 作为底层支撑。

## 一、已实现

> 基于全工程代码核对。

### 1. 微服务架构

**9 个 Java 微服务 + 1 个 Python AI 服务 + 1 个 Vue3 前端**：

| 模块 | 职责 |
|---|---|
| `cyxz-gateway` | 网关：JWT 鉴权、路由、信任头注入、CORS |
| `cyxz-auth` | 认证：注册、登录、验证码、密码修改、用户管理 |
| `cyxz-user` | 用户：资料、关注关系、内部批量查询 |
| `cyxz-post` | 帖子：CRUD、状态机、审核、互动（点赞收藏浏览）、数据中心 |
| `cyxz-comment` | 评论：评论、回复、点赞、嵌套结构、计数同步 |
| `cyxz-circle` | 圈子：CRUD、加入退出、板块模板、计数同步 |
| `cyxz-upload` | 上传：头像、帖子图片、圈子资源（MinIO） |
| `cyxz-message` | 消息：通知中心、私信、WebSocket 推送、MQ 消费 |
| `cyxz-search` | 搜索：ES 帖子搜索、MQ 增量同步、全量同步 |
| `cyxz-ai`（Python） | AI 审核：文本审核（DeepSeek）、图片审核（千问 VL） |
| `cyxz-frontend`（Vue3） | 前端：Pinia + Vue Router + Element Plus + ECharts |

**API 模块**：`cyxz-auth-api` / `cyxz-user-api` / `cyxz-post-api` / `cyxz-circle-api` / `cyxz-comment-api` / `cyxz-message-api`，统一 `com.cyxz.{module}.feign/vo/dto` 包结构。

### 2. 圈子服务拆分（已完成）

原稿规划"将圈子领域从 `cyxz-post` 拆分为独立 `cyxz-circle` 服务"，**已实现**：

```
cyxz-circle
├─ circle、circle_member、circle_section、section_template 表
├─ 圈子列表、详情、加入、退出、我的圈子
├─ member_count 本地事务维护
├─ 发布前校验接口 /circle/internal/{circleId}/publishable
└─ 定时通过 Feign 查询 post 服务已发布帖子数 → 覆盖写入 circle.post_count

cyxz-post
├─ post 表、circle_id
├─ 按 circle_id 查询帖子流
├─ 提供 /internal/batch-circle-post-count 供 circle 查询
└─ 发布前调用 Circle 校验
```

**帖子数同步**：`CircleCountFlushTask` 每 60 秒通过 Feign 批量查询各圈子已发布帖子数（status=2），直接 `SET post_count = ?` 覆盖写入，无增量写入、无 Redis 中转、无重复计数。

**发布权限**：新帖必须选择已加入且启用的圈子，前端只展示已加入圈子，后端通过 Feign 同步校验 publishable，覆盖创建、草稿转发布、批量发布。

### 3. 消息通知系统（已完成）

原稿规划"关注动态流"，**已实现完整消息系统**：

- 7 种通知类型（点赞、评论、回复、收藏、关注、审核通过、审核拒绝）
- MQ 异步落库 + WebSocket 实时推送
- 手动 ACK + 死信队列
- 私信能力（会话列表、历史消息、发送、标记已读）
- 关注动态流（`GET /post/following` 拉模式时间线）

详见 [消息通知与关注动态方案.md](./消息通知与关注动态方案.md)。

### 4. AI 审核 + 人工兜底（已完成）

- Python `cyxz-ai` 服务（FastAPI）
- 文本审核：DeepSeek LLM
- 图片审核：通义千问 VL 多模态
- fail-closed：AI 不可用时拒绝发布
- 人工兜底：AI 异常时保持 PENDING 转后台

详见 [AI能力设计.md](./AI能力设计.md)。

### 5. 管理后台（已完成）

- 管理员鉴权：`@AdminUser` 注解 + 网关 `X-User-Role` 信任头
- 帖子审核：`pending/approve/reject` 接口
- 帖子状态机：`ALLOWED_TRANSITIONS` 表 + `canTransition` 校验
- 圈子管理：CRUD + 板块"模板 + 关联"两层模型
- 敏感词检测：静态文件加载

详见 [管理后台设计.md](./管理后台设计.md)。

### 6. ES 搜索（已完成）

原稿规划"第一阶段 MySQL LIKE，后期 Elasticsearch"，**已实现 ES**：

- `cyxz-search` 独立服务
- `SearchController`：关键词搜索、圈子过滤、热度/时间排序、高亮
- `PostEsSyncConsumer`：MQ 消费 ES 同步事件，手动 ACK + 死信队列
- `EsFullSyncRunner`：启动时全量同步兜底
- 分页参数防御：page 最小 1，size 限制 1~50

### 7. 跨服务计数同步（已完成）

**Redis Hash 增量 + 定时刷库**方案：

| 模块 | 计数 | 刷库周期 |
|---|---|---|
| `cyxz-post` | 浏览、点赞、收藏、评论数 | 30 秒 |
| `cyxz-comment` | 评论点赞数 | 定时刷库 |
| `cyxz-circle` | 圈子帖子数 | 60 秒（Feign 拉取覆盖写入） |

关系表照常写，计数通过 Redis Hash 增量记录，定时任务统一刷库，避免高并发下频繁 UPDATE。

### 8. 工程基础设施（已完成）

- **CI**：GitHub Actions（`.github/workflows/ci.yml`），后端 `mvn test`、前端 `npm test && npm run build`
- **配置中心**：Nacos 服务发现 + 配置
- **消息队列**：RabbitMQ，TopicExchange + 死信队列
- **缓存**：Redis，Hash 增量计数 + Bitmap（规划）
- **文件存储**：MinIO（头像、帖子图片、圈子资源）
- **数据库**：MySQL，`db/init.sql` 初始化脚本
- **全局异常处理**：`GlobalExceptionHandler` 统一错误响应
- **JWT 鉴权**：网关 `JwtAuthFilter` + 服务侧 `@CurrentUser` / `@AdminUser` 注解

## 二、规划

### P0：用户反馈与举报治理

**反馈工单**

```
入口：头像下拉 / 个人中心
类型：功能建议 / Bug 反馈 / 内容举报 / 其他
后台：待处理 → 处理中 → 已解决 → 已关闭
管理员回复 + 站内通知
```

**举报**

```
举报帖子 / 评论
后台审核队列
处理：隐藏 / 驳回 / 删除
审计日志
```

### P1：二次元特色内容

**帖子投票**

```
一帖一个投票，2~6 个选项，单选
每人限投一次，可设截止时间
归 post 领域，不拆独立服务
```

**创作挑战 / 主题活动**

```
管理员创建活动：标题、封面、时间范围
用户发帖参与
活动页聚合作品
```

**作品系列 / 合集**

```
系列 → 章节/条目
帖子详情展示上下篇与目录
适合漫画连载、OC 设定、攻略系列
```

**追更中心**

```
作品/角色/版本资料页
关联圈子与最新讨论
管理员后台维护少量作品资料
```

**约稿 / 创作招募**

```
帖子类型扩展：约稿需求、稿件展示、合作招募
结构化字段：预算、截止、标签
不做支付与担保
```

### P2：社区体验

**收藏夹**

```
公开/私密收藏夹
灵感收集、攻略汇总、佳作收藏
```

**新用户引导**

```
注册后选择感兴趣的作品/圈子
关注推荐创作者
进入个性化发现页
初期规则驱动，不依赖推荐算法
```

**同担社交**

```
个人资料标签：主推作品、常驻圈、创作方向
帖子/评论处展示共同标签
仅做表达，不做匹配算法
```

**帖子内容类型**

```
post_type：图文分享、长文考据、攻略清单、投票、作品集、活动投稿
统一扩展框架，不硬塞字段
```

### P3：运营与内容

**编辑精选**

```
每日精选、本周创作、新星创作者
后台人工选，首页小区域展示
冷启动期替代推荐算法
```

**搜索升级**

```
帖子、圈子、用户、标签统一搜索
搜索结果分 Tab
当前已实现帖子 ES 搜索，圈子/用户搜索待补
```

## 三、工程与架构规划

### cyxz-job 统一任务编排

```
凌晨对账调用：
  → POST /internal/reconcile/circle-post-count
  → POST /internal/reconcile/circle-member-count
  → POST /internal/reconcile/post-interaction-count
  → POST /internal/reconcile/comment-like-count

不直接查各服务数据库，只调用业务内部接口
任务执行记录、失败重试、管理端手动执行
后期可接入 XXL-JOB / PowerJob
```

**当前状态**：各服务已有独立 `CountFlushTask`（post 30s / circle 60s），但无统一编排和审计。

### 审计日志

```
管理员操作日志
关键用户行为记录
操作者、对象、前后状态、时间
配合审核与治理
```

**当前状态**：未实现，管理员操作仅通过 `@AdminUser` 鉴权，无操作日志记录。

### 可观测性与部署

```
健康检查
接口耗时与错误统计
MQ 死信监控
Redis 增量 Key 积压观测
Docker Compose 一键部署
GitHub Actions CI
```

**当前状态**：

- CI 已实现（GitHub Actions）
- 健康检查：`cyxz-ai` 有 `/health`，Java 服务无 actuator 暴露
- 死信监控：`PostEsSyncConsumer` / `NotificationEventConsumer` 有日志，无告警

### 文件与图片治理

```
上传任务状态
图片压缩与缩略图
引用计数
孤儿文件清理
后续对接 MinIO / 对象存储
```

**当前状态**：

- 删除接口有归属校验（`avatar/{userId}/...` 和 `post/image/{userId}/...`）

## 五、技术亮点（简历视角）

1. **微服务拆分清晰**：9 个 Java 服务 + 1 个 Python AI 服务，按领域边界拆分，API 模块统一包结构
2. **跨服务计数同步**：Redis Hash 增量 + 定时刷库，避免高并发 UPDATE，圈子帖子数走 Feign 覆盖写入
3. **MQ 异步解耦**：通知、ES 同步、死信队列，业务事务与异步任务解耦
4. **状态机强约束**：帖子状态流转通过 `ALLOWED_TRANSITIONS` 表校验，避免非法跃迁
5. **两段式鉴权**：网关注入信任头 + 服务侧注解校验，防伪造剥离
6. **跨语言架构**：Java 主业务 + Python AI 服务，HTTP 解耦，fail-closed 降级
7. **ES 增量同步**：MQ 事件驱动，启动全量同步兜底，手动 ACK + 死信队列
8. **CI 自动化**：GitHub Actions 后端 `mvn test` + 前端 `npm test && npm run build`
