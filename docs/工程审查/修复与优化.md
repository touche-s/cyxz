## 一、本轮修复（6 项）

### 1. 统一帖子状态常量到 PostStatus（P0 根因修复）

**问题**：帖子状态码散落硬编码，`PostInteractionServiceImpl` 用 `== 2`、`PostLikeMapper` SQL 用 `status = 1`，与 `PostServiceImpl` 的常量定义不一致，导致互动功能对正常帖子完全失效。

**修复**：
- 新增 `PostStatus` 公共常量类（5 状态 + `canTransition` 流转规则 + `label`）
- `CommonStatus` 职责收敛为关系表二态（ACTIVE/DELETED），类注释指引区分
- `PostServiceImpl` / `PostInteractionServiceImpl` 移除内部常量，引用 `PostStatus.*`
- `PostLikeMapper` SQL 硬编码添加 `/* PostStatus.APPROVED */` 注释

**涉及文件**：PostStatus.java(新增)、CommonStatus.java、PostInteractionServiceImpl.java、PostLikeMapper.java、PostServiceImpl.java

---

### 2. AI 审核 fail-closed（P0 安全）

**问题**：AI 审核链路三处 fail-open——未配 API Key 时自动放行所有内容；AI 返回空时直接 `passed=true`；手拼 JSON 有注入风险；reviewer.py 直接下载用户可控 URL（SSRF）。

**修复**：
- `config.py`：`AUTO_PASS_WITHOUT_KEY` 默认 `"true"` → `"false"`（fail-closed）
- `AiReviewService`：注入 ObjectMapper，手拼 JSON 改 `writeValueAsString`；null body 返回 `AiReviewResult(false, "审核服务异常")`
- `reviewer.py`：加 `_validate_image_url`（协议校验 + 禁止云元数据 host）+ 下载大小限制 10MB

**涉及文件**：config.py、AiReviewService.java、reviewer.py

---

### 3. batchOperate 状态机绕过 + 异步竞态（P1）

**问题**：`batchUpdateStatus` SQL 无状态条件，已发布帖会被打回 PENDING；`@Transactional` 内 `CompletableFuture.runAsync` 在事务提交前派发，`handleReviewResult` 读到旧状态跳过审核。

**修复**：
- `PostMapper.batchUpdateStatus` 加 `fromStatus` 参数 + `<if>` 条件；publish 传 `DRAFT`，delete 传 `null`
- 异步任务包装在 `TransactionSynchronizationManager.registerSynchronization` 的 `afterCommit` 中

**涉及文件**：PostMapper.java、PostServiceImpl.java

---

### 4. ES 同步补全死信队列（P1）

**问题**：`SearchRabbitConfig` 无 DLX/DLQ，消费者 `basicReject(tag, false)` 直接丢消息，ES 临时不可用时 DB 与 ES 数据永久不一致。

**修复**：
- `EsSyncConstants` 加 DLX/DLQ/DEAD_ROUTING_KEY 常量
- `SearchRabbitConfig` 主队列绑定 DLX，加死信交换机/队列/绑定
- `PostEsSyncConsumer` 加 `onDeadLetter` 死信消费者记录失败消息

**涉及文件**：EsSyncConstants.java、SearchRabbitConfig.java、PostEsSyncConsumer.java

---

### 5. Redis 反序列化类型白名单（中危安全）

**问题**：`GenericJackson2JsonRedisSerializer` 默认写 `@class` 类型信息，Redis 被入侵后可触发任意类反序列化（RCE）。

**修复**：配置 `BasicPolymorphicTypeValidator` 白名单，仅允许 `com.cyxz`/`java.util`/`java.lang`/`java.time` 包的类被反序列化，保持 `@class` 兼容同时阻断危险类。

**涉及文件**：RedisConfig.java

---

### 6. AI 审核异常转人工流转（P1）

**问题**：AI 审核异常时仅 `log.error("转人工审核")`，无实际转人工逻辑，帖子永久卡 PENDING。

**修复**：新增 `handleReviewFailure` 方法——异常时帖子保持 PENDING，设置 `reviewReason="AI审核服务异常，待人工审核"`，管理员通过后台 `listPendingReview` 列表手动处理。三处 catch 块（createPost / updatePost / batchOperate）统一调用。

**涉及文件**：PostServiceImpl.java
